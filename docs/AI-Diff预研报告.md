# 选区 diff 分块预研报告（R9 / FR-AI-02 / M4）

- 日期：2026-10-21
- 结论：**可行——但不采用 prosemirror-diff 类方案，改为自研文本级 token diff + 块级预览/接受**。FR-AI-02 P0 范围维持"逐块接受/拒绝"，无需启用降级方案。

## 候选方案评估

| 方案 | 评估 | 结论 |
|---|---|---|
| prosemirror-diff（社区库，基于 ProseMirror Step/Node diff） | ① 最后更新多年前，与 TipTap 3 / ProMirror 最新 API 的兼容性无官方背书（R10 第三方单点风险）；② 其输出面向"补丁 Steps"，与"按修改块给人看并逐块勾选"的交互模型不匹配，仍需二次聚合；③ 面向整文档 diff，选区场景（几百字）开销浪费 | 不采用 |
| diff-match-patch（Google） | 成熟稳定，但输出为字节级 op 流，CJK 逐字 diff 需自己分词归并；引入依赖换来的核心算法（Myers）本身 ~100 行可自研 | 不采用（减少 R10 单点） |
| **自研：token 化 + LCS diff + 块聚合**（本报告采纳） | 选区文本先 token 化（CJK 逐字、西文/数字逐词、空白归并），LCS 求公共序列（选区 ≤ 数千 token，O(n·m) DP 在 500 字选段为毫秒级），相邻增/删/改聚合成"修改块"；逐块接受 = 拼装接受块 + 未改原文 → **一次性事务替换选区** | 采用 |

## 关键设计决定

1. **块级接受的撤销语义**：无论接受多少块，应用时走**单个 ProseMirror transaction**（一次 replaceRange），
   因此"半份应用成功 + 一次 Ctrl+Z 整体还原到润色前"（AC A5）天然成立——不需要为每个块构造独立可逆 Step。
2. **diff 在文本层（markdown 字符串）进行**，不在 PM 节点层：
   - 选区内容经 DocModel → md 文本 → 润色 → diff → 预览；接受后 md → DocModel → 替换选区；
   - 全程复用 DocumentCodec（M11），导出器/编辑器共用同一映射，零额外节点级位置映射负担——这正是 R9 担忧的"块级 diff 与 ProseMirror 位置映射实现难度高"的规避点。
3. **修改块定义**：连续的同向变更（删除段 + 紧随的插入段视为同一"改"块），块间由未变上下文分隔；每块保留前后各 ~12 字上下文供人工比对。
4. **流式中途取消不产生半块**：diff 只对**完整响应**计算；流式阶段仅展示"处理中"状态与已生成字数，不进入 diff 视图。

## 实现落点

- `src/diff.ts`：token 化 + LCS + 块聚合（纯函数，无编辑器依赖，可 node 测试）；
- `tests/ai-diff.mjs`：分块正确性（改/增/删/CJK 与西文混排）、无变化时空块、大选段性能冒烟；
- 润色应用路径：`store.ts applyPolish()` —— 单 transaction 替换 + pre_ai 快照（应用前自动保存，来源标记 `pre_ai`，FR-AI-02）。

## 风险与后续

- 超大选区（>5000 字）性能：LCS DP 需 ~25M 单元，JS 下约百毫秒级——可接受；如出现卡顿，V1.2 可换 Myers 线性空间变体（接口不变）。
- 富格式选区（表格/列表内）：diff 在纯文本层进行，接受后整段以 md 重解析替换，格式由 codec 保证往返（codec-roundtrip 已回归）。
