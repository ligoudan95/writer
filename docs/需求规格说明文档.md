## 1. 引言

### 1.1 编写目的

本文档定义个人桌面写作软件（项目代号 **Writer**）第一版及后续版本的软件需求，作为设计、开发、测试与验收的依据。

### 1.2 项目背景

面向个人写作者（小说作者、博客作者、随笔爱好者）的本地优先桌面写作软件。核心卖点：**专业级文本编辑 + 多格式导出 + WebDAV 云同步 + 内置 AI 辅助写作**。

### 1.3 已定案的关键决策

| # | 决策项 | 结论 |
|---|---|---|
| D1 | 技术栈 | **Tauri 2 + Vue 3 + TypeScript + TipTap**（详见 2.4） |
| D2 | 目标平台 | **仅 Windows**（10/11 x64），架构不引入平台锁定 |
| D3 | 云端形态 | 第一版接入 **WebDAV 协议**（坚果云等现成网盘），不自建同步服务器 |
| D4 | DOC 导出 | **彻底移除**（v1.1 定案）：不提供 DOC 格式导出，Word 兼容 HTML 方案一并放弃。导出格式集 = TXT / MD / DOCX / PDF + 未来扩展 |

### 1.4 术语与缩略语

| 术语 | 说明 |
|---|---|
| 库（Library） | 用户全部文稿的根容器，本地为一个文件夹 |
| 文档（Document） | 一篇正文的逻辑单元，本地对应一个 `.md` 文件 |
| frontmatter | Markdown 文件头部的 YAML 元数据块，存放 uuid、标签、创建时间等 |
| 快照（Snapshot） | 文档某一时刻的完整内容备份，用于版本历史回滚 |
| 墓碑（Tombstone） | 已删除文档的记录清单，用于向其他同步设备传播删除 |
| WebDAV | 基于 HTTP 的文件传输协议，坚果云等网盘支持 |
| Provider | AI 服务提供方（OpenAI 兼容 API 的接入配置） |
| P0 / P1 / P2 | 优先级：P0 第一版必须；P1 紧随第一版（V1.1/V1.2）；P2 远期版本 |
| FTS | Full-Text Search，全文检索 |
| diff | 文本差异对比 |
| LibraryService / NetGateway / DocumentCodec | 核心组件：库文件**单写者队列** / **唯一网络出口** / md↔DocModel **无头编解码器**（见第 3、5 章） |

## 2. 总体描述

### 2.1 产品定位与目标

1. **本地优先**：所有数据完整保存在本地，断网全功能可用；云端只是同步通道。
2. **数据主权**：正文以明文 Markdown 存储，用户随时可将整个库文件夹拷走，不做数据绑架。
3. **AI 增强而非 AI 绑架**：AI 功能全部可配置、可关闭；改动永远可预览、可撤销。
4. **轻快**：安装包小、启动快、长文档不卡。

### 2.2 目标用户与使用场景

- 网文/小说作者：多章节长篇管理、人物设定、日更统计、AI 续写找思路。
- 博客/专栏作者：Markdown 写作、一键导出 MD/DOCX/PDF 发布。
- 随笔/日记用户：多设备同步、全文搜索旧文。

### 2.3 产品范围

**V1.0（首个发布）做**：文档与库管理、富文本编辑器（含表格）、自动保存与版本历史、TXT/MD/DOCX/PDF 导出、TXT/MD/DOCX 导入、WebDAV 同步（含删除与改名传播、首次绑定方向确认、打开文档远端更新协议）、AI 润色/续写/讨论、AI 隐私保护、字数统计、格式工具栏、通知中心与打扰治理、首次运行零配置上手、亮暗主题、单实例与库锁定、诊断与备份、成品安装包（安全安装/卸载、WebView2 引导与开源许可合规，第 11 章）。

**V1.0 不做、后续版本做**：本地全文搜索（V1.1）、写作目标与统计（V1.1）、标签收藏（V1.1）、专注模式（V1.1）、库体检与修复（V1.1）、存储空间面板（V1.1）、备份恢复向导（V1.1）、合并导出与 PDF 高级排版（V1.2）、联网 AI 搜索（V1.2）、图片操作（V1.2）、人物卡/世界观设定集（V2）、插件系统（V2）、端到端加密同步（V2）、多语言界面（V2）。

**明确不做**：DOC 格式导出（决策 D4，已彻底移除）；协作与账号体系（无计划）；便携版发布（V1 仅预留模式开关，FR-PKG-04）。

### 2.4 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用框架 | Tauri 2（Rust 核心 + 系统 WebView2） | 安装包小、内存占用低、Rust 侧适合文件 IO / SQLite / WebDAV / 导出等重活 |
| 前端框架 | Vue 3 + TypeScript + Vite | 中文生态成熟；TipTap 官方完整支持 |
| 编辑器 | TipTap（基于 ProseMirror） | 可扩展的富文本骨架，Markdown 序列化、diff 均有生态 |
| 本地存储 | 正文 = `.md` 文件（含 frontmatter）；索引/元数据 = SQLite（**Rust 侧唯一属主**，前端经类型化 command 访问，不经 tauri-plugin-sql 直连） | 满足"数据可迁移"P0 需求；SQLite 可随时由 md 文件重建；避免前后端并发写库与 schema 耦合 |
| 全文检索 | **混合策略**：≥3 字查询走 SQLite FTS5 trigram 索引；≤2 字中文查询回退 LIKE 顺序扫描（目标库规模下毫秒级）；备选 Rust 侧 tantivy | trigram 不支持 2 字子串，必须回退；见风险 R4 |
| DOCX 导出 | 前端 `docx` 库（由统一文档模型生成） | 成熟、无需 Office 环境 |
| PDF 导出 | 排版模板（HTML/CSS + **Paged.js 分页渲染，M2 预研验证**）+ WebView2 `PrintToPdf` 管线，渲染在**专用离屏 webview（PDF 渲染舱）**进行 | 中文字体渲染由系统保证；页码/页眉页脚等依赖分页感知的高级排版为 P1，视预研结论落地；渲染不占用编辑区、不产生界面闪烁 |
| WebDAV | Rust 侧 reqwest 实现 WebDAV 客户端（含 MOVE 支持，用于改名传播） | 网络与凭据处理留在 Rust 核心 |
| AI 接入 | OpenAI 兼容 Chat API（自定义 Base URL + Key + Model），SSE 流式；**全部流量经 Rust NetGateway 出口**（规避 WebView CORS 限制、执行 NFR-12 白名单、支持取消传播），前端以事件流消费 | 不绑死任何 Provider；无 CORS 头的自建/中转端点同样可用 |

### 2.5 运行环境

- Windows 10 1809+ / Windows 11，x64。
- 依赖 WebView2 运行时（Win11 及多数 Win10 已内置；安装器检测缺失时引导安装，见风险 R3）。

## 3. 系统架构

### 3.1 分层结构

```
┌──────────────────────────────────────────────┐
│ UI 层（Vue 3 + TipTap，运行于 WebView）          │
│  编辑器 / 文档树 / AI 面板 / 搜索 / 设置 / 统计    │
├──────────────────────────────────────────────┤
│ 应用服务层（TypeScript，前端侧）                  │
│  文档模型 / DocumentCodec / 状态管理 /            │
│  Exporter 调度 / AI 流式消费                     │
├═══ Tauri command 契约（稳定 API，见 5.3）════════╡
│              ▲ 领域事件推送（见 5.4）             │
│ Rust 核心                                       │
│  LibraryService（库文件单写者队列，3.3-6）        │
│  NetGateway（唯一网络出口，3.3-7）/ Secrets      │
│  SQLite·FTS 唯一属主 / WebDAV / PDF 渲染舱        │
│  备份 / 更新 / 日志 / 事件总线                    │
├──────────────────────────────────────────────┤
│ 契约层（第 5 章）：Rust trait + 前端 TS 接口      │
│  StorageBackend / Exporter / AIProvider …       │
└──────────────────────────────────────────────┘
```

### 3.2 模块划分

| 模块 | 职责 |
|---|---|
| M1 库与文档管理 | 库的创建/打开、文档树、回收站、标签、附件管理 |
| M2 编辑器 | TipTap 编辑、Markdown 互转、专注模式、字数统计 |
| M3 存储与版本 | 自动保存、快照与版本历史、崩溃恢复 |
| M4 导入导出 | Exporter 插件调度、导入解析、合并导出 |
| M5 同步 | WebDAV 适配器、增量同步、冲突处理、删除/改名传播、首次绑定 |
| M6 搜索 | 混合索引（FTS + LIKE）、跨文档检索 |
| M7 AI | Provider 管理、润色/续写/讨论、diff 应用、Prompt 模板 |
| M8 统计 | 写作目标、日/周/月字数统计 |
| M9 设置与主题 | 偏好设置、亮暗主题、编辑区排版设置 |
| M10 更新与诊断 | 自动更新、日志、备份管理 |
| M11 文档编解码（DocumentCodec） | md ↔ DocModel 双向转换，**独立于编辑器实例**；编辑器、导出、搜索索引、AI 上下文统一消费；往返一致性测试（FR-EDT-01 AC）的基准 |

**Rust 核心服务（横切组件，不属于功能模块）**：

| 服务 | 职责 |
|---|---|
| LibraryService | 库文件**单写者队列**：一切写入/改名/移动/删除/重排/墓碑变更的唯一入口；快照与备份在队列静默点取一致视图（3.3 原则 6） |
| NetGateway | **唯一网络出口**：AI / WebDAV / 更新检查全部流量经此发出，按配置执行域名白名单（NFR-12 执行点）；abort 信号传播（FR-AI-08） |
| Secrets | DPAPI 凭据加密存取（WebDAV 密码、AI Key），前端永不接触明文（NFR-08） |
| DB 属主 | meta.db / sync_state.db 的连接、事务与 schema 迁移唯一属主（NFR-10）；前端经类型化 command 访问 |
| 事件总线 | 领域事件向前端推送（契约见 5.4），替代轮询 |
| PDF 渲染舱 | 离屏 WebView：Paged.js 分页渲染与打印（FR-EXP-05），与编辑区隔离（配合 NFR-15 内容隔离） |

### 3.3 核心设计原则（约束所有需求实现）

1. **离线优先**：任何功能不得以"必须联网"为前提（AI 调用本身除外，但 AI 不可用时软件其余功能完好）。
2. **接口开放**：导出格式、存储后端、AI Provider 均以接口抽象，新格式/新网盘/新模型 = 新增一个实现类，不改核心（见第 5 章）。
3. **用户数据明文可迁出**：不允许任何核心数据仅存在于私有二进制格式中。
4. **AI 改动必须可逆**：所有 AI 修改在应用前有 diff 预览，应用后可一键撤销。
5. **心流优先（打断最小化）**：模态弹窗仅限破坏性确认与首次同步方向选择；其余一切通知非模态并沉淀至通知中心；用户输入中的非紧急通知自动延后（细则见 FR-UI-06）。
6. **库文件单写者**：库内一切文件与数据库变更（写入、改名、移动、删除、重排、墓碑）必须经 Rust 侧 LibraryService 串行队列执行，任何组件不得绕过队列直写磁盘；快照与备份在队列静默点取一致视图。
7. **唯一网络出口**：全部网络流量（AI、WebDAV、更新检查）经 Rust NetGateway 发出并做域名白名单校验；前端不发起任何直接网络请求——这是 NFR-12 的技术执行点，同时规避 WebView 的 CORS 限制。

## 4. 功能需求

编号规则：`FR-<模块>-<序号>`。每条含优先级与验收标准（AC）。

### 4.1 库与文档管理（FR-DOC）

**FR-DOC-01 库管理**（P0）
支持"新建库 / 打开已有库（选择文件夹）/ 最近打开的库"。V1 单库运行（一次打开一个库），多库切换通过重新打开实现。同一库不可被两个实例同时打开（见 FR-SET-04）。
**启动序列（固定）**：加锁（FR-SET-04）→ 配置/格式/DB 版本迁移（NFR-10）→ 磁盘扫描对账（uuid/id 校验，FR-SYN-08/FR-IMP-01 规则）→ 索引增量更新 → 会话恢复（FR-UI-04）→ 界面就绪。任一步失败均有明确降级路径；**迁移中断恢复**：启动检测到上次迁移未完成 → 回滚至迁移前自动备份并重试一次，仍失败则库以只读模式打开并引导库体检（FR-DOC-07）。
AC：新建库后在所选位置生成标准库目录结构（见 6.3）；重启后自动恢复上次打开的库。

**FR-DOC-02 文档树**（P0）
左侧栏树状组织：文件夹（书/分类）→ 子文件夹 → 文档（章节）。支持新建/重命名/删除/拖拽排序与移动。**支持至少 5 级嵌套**；创建/重命名/移动时校验 Windows 完整路径 ≤ 260 字符，超限阻断并提示。
**排序规则（同步相关，固定）**：
- 文档树默认按**文件名自然排序**（序号即顺序，随文件同步天然保持多端一致）；从未使用手动排序的文件夹不加前缀，文件名即标题；
- **前缀仅是排序元数据**：文档树、标题栏、导出文件名一律**剥离前缀显示标题**（前缀格式 `N-标题`）；
- **重排策略（防改名风暴）**：启用手动排序的文件夹按**步长 10** 编号（`10-`、`20-`…），插入新文档优先占用空档编号，空档耗尽才对该文件夹**局部**重排，禁止无差别全量改名；
- **拖拽反馈**：拖拽时显示插入位置指示线；重命名与远端 MOVE 完成前，受影响节点显示"排序同步中"角标；
AC：拖拽文档到文件夹即移动（底层 md 文件同步移动）；拖拽调整顺序后文件名序号自动更新且顺序在另一台同步设备上一致；100 章文件夹中插入新章时利用空档编号，既有文件零重命名。

**FR-DOC-03 回收站**（P0）
删除文档/文件夹为软删除：文件移入 `.writer/trash/`（保持原相对路径结构，不同步）；删除动作通过墓碑清单向其他设备传播（见 FR-SYN-08）。回收站内可还原或彻底删除；保留 30 天后提示清理（不自动删）。
**删除交互（撤销式）**：单篇删除即时生效、不做确认弹窗，以右下角"已移入回收站 · 撤销"通知替代（5 秒内可撤销，FR-UI-06 体系）；批量删除文件夹仍走模态确认（白名单内）。回收站入口固定于侧栏底部（常驻可见）。
AC：从回收站还原后文档回到原位置（原位置已不存在时回到库根）；被删除文档不会因同步被"复活"（A11）。

**FR-DOC-04 标签与收藏**（P1）
文档可打多个标签（存于 frontmatter），支持按标签筛选；支持收藏置顶。
AC：标签在另一台同步设备上可见（依赖 frontmatter 同步）。

**FR-DOC-05 文档属性**（P0）
显示/编辑：标题、创建时间、最后修改时间、字数；正文文件名 = 标题（自动去非法字符、同文件夹内重名自动加序号；启用手动排序的文件夹为 `序号-标题`，前缀剥离规则见 FR-DOC-02）。改名经同步以 MOVE 传播（见 FR-SYN-08），不视为"删除+新建"。
**新建命名流（固定）**：新建文档即时命名"无标题 N"（N 递增），侧栏/顶栏就地重命名（Enter 确认、Esc 取消）；不做"首行即标题"的隐式行为。导出去重：正文首个 H1 与文档标题相同时不重复输出标题（各 Exporter 统一遵循）。
AC：修改标题后磁盘 md 文件名在 2 秒内同步更新。

**FR-DOC-06 附件管理**（P2）
附件面板：列出 `attachments/` 全部文件、跳转被引用位置、未引用检测、批量清理。新附件命名规则：`yyyyMMdd-序号.ext`；附件按**内容 hash 去重**（重复粘贴同一图片复用同一文件，不重复存储与同步）；图片粘贴失败（格式不支持/磁盘错误）有明确非模态提示。
AC：清理操作仅删除"零引用"附件，二次确认后执行；引用中的附件不可删除（置灰并说明原因）。

**FR-DOC-07 库体检与修复**（P1）
一键体检并逐项给出修复动作：frontmatter id 缺失/重复、编码异常文件、索引与 md 内容不一致、僵死锁文件、孤儿附件、损坏的墓碑清单；修复前自动备份，全部动作写入日志。本功能是风险 R8 各场景的统一处理入口。
AC：人为制造"两文件同 uuid + 缺 id 文件"后体检，两项均被检出且可一键修复（重分配 uuid），修复后同步正常。

### 4.2 编辑器（FR-EDT）

**FR-EDT-01 富文本格式集**（P0）
**序列化方言（固定）**：CommonMark + GFM 扩展（表格、任务列表、删除线）+ 高亮 `==文本==` + 下划线以 `<u>` HTML 直写（Typora 兼容）。
支持格式：标题 H1–H6、粗体、斜体、下划线、删除线、行内代码、代码块、有序/无序列表、任务列表、引用、链接、图片、**表格**、分割线；高亮（P1）。
**范围决策**：V1 不支持行内任意字号/颜色（无法存入标准 Markdown）；字号、字体、行距、首行缩进作为"文档级排版设置"作用于显示与导出（见 FR-UI-03）。
AC：每种格式在编辑器中正确渲染；**往返序列化测试针对 DocumentCodec（3.2 M11）**——md → DocModel → md 无损，编辑器加载与导出消费同一转换器（保证"所见"与"所得"一致）；导出的 MD 在 Typora/VS Code 中语法正确（含 GFM 表格与 `<u>`）。

**FR-EDT-02 Markdown 快捷输入**（P0）
支持 Markdown 语法直接键入（输入 `# ` 变标题、`**` 包裹变粗体等，Typora 式）；支持常用 Markdown 快捷键（Ctrl+1~6 标题、Ctrl+B/I/U 等，见附录 A）。链接交互：Ctrl+点击经系统默认浏览器打开（首次外发确认一次）；选中链接可编辑 URL 与显示文字。

**FR-EDT-03 撤销与重做**（P0）
撤销/重做（Ctrl+Z / Ctrl+Y），撤销栈不因自动保存而清空。AI 应用改动、拖拽重排序号重命名均作为单一撤销单元。
**撤销栈上限（v1.7.1 定案）**：单会话内按"**500 步或 256 MB 先到为准**"淘汰最早记录（与 NFR-05 内存预算匹配）；被淘汰区段的回退由版本历史/快照兜底。
**已知限制（明示）**：撤销栈不跨会话——关闭并重开文档后，上一会话的操作不可撤销（由版本历史/快照兜底回滚）。

**FR-EDT-04 中文写作支持**（P0）
- 中文输入法组合输入（IME composition）不丢字、不跳光标。
- 智能标点可开关：输入英文引号/括号自动配对为中文全角。
- 中文首行缩进 2 字符：**默认开启**（贴近 Word/网文用户直觉，v1.3 定案），设置可全局关闭，按文档记忆覆盖。**缩进属排版型属性（v1.7 定案）**：屏幕显示与 PDF/DOCX 导出遵循；MD/TXT 无对应语法、导出不携带（各自提供可选"转全角空格"，默认关，见 FR-EXP-02/03）。
- 避头尾规则（行首不出句读类标点）由 WebView 排版引擎保证。
AC：连续中文输入 1 万字无丢字；标点悬挂正确。

**FR-EDT-05 专注模式**（P1）
三种可叠加：无干扰全屏（隐藏侧栏）、打字机模式（当前行保持视口垂直居中）、段落聚焦（非当前段落降低透明度）。

**FR-EDT-06 大纲导航**（P0）
侧栏大纲面板按标题层级展示当前文档结构，点击跳转；支持在大纲中拖拽标题调整章节顺序（P1）；跳转后提供"返回跳转前位置"导航（P2）。

**FR-EDT-07 字数统计栏**（P0）
状态栏实时显示：字数、字符数（计/不计空格）、段落数、预计阅读时长（中文 400 字/分钟）。光标选中时显示选中部分统计。
**计数规则**：CJK 字符按单个计；连续西文/数字串按 1 个词计（与 Word 习惯一致）；统计采用分段缓存 + 增量更新（逐键 O(1)，不随全文重算，支撑 NFR-03）。
AC：与 Word 对同一段中英混排文本的字数统计误差 ≤ 2%。

**FR-EDT-08 多标签与分屏**（P1 / P2）
多标签页同时打开多篇文档（P1）；左右分屏对照（P2）。
**实例缓存（实现约束）**：多标签启用前，编辑器实例按 LRU 缓存最近 3 篇文档（NFR-05 内存预算内），切换回即恢复光标与滚动。

**FR-EDT-09 格式工具栏**（P0）
可隐藏的格式工具栏：标题、加粗、斜体、下划线、删除线、有序/无序列表、引用、表格、链接、图片按钮；**跟随选区实时高亮当前格式态**；悬停显示功能名与快捷键。设置可切换"工具栏 + 快捷键 / 仅快捷键"；专注模式（FR-EDT-05）下自动隐藏。保证不熟悉 Markdown 的用户全部格式功能可发现、可点击。
**表格浮动工具条**：光标位于表格内时显示（增删行/列、表头切换、单元格合并、删除表格）——表格编辑的操作载体，M1"表格编辑基线"验收含全部行列操作。
AC：仅用工具栏（不碰任何 Markdown 语法与快捷键）可完成 FR-EDT-01 全部格式的施加与取消。

**FR-EDT-10 输入体验特色**（P2）
打字音效（多套可选、音量与总开关）；中英混排自动加空格（盘古之白，可开关）——两者均只在**显示层与导出层**生效，不改动存储的正文内容。

**FR-EDT-11 图片操作**（P1，V1.2）
图片选中态浮动操作：宽度百分比（25%–100%）、对齐（左/中/右）、放大查看、替换、另存为；宽度与对齐以 Markdown 图片语法的扩展参数存储（方言文档记录，标准兼容性不受影响）。

### 4.3 查找替换（FR-FND）

**FR-FND-01 文档内查找替换**（P0）
Ctrl+F / Ctrl+H：当前文档内查找与替换；大小写敏感、全字匹配、正则模式三开关；显示**匹配计数**，提供上一个/下一个导航（Enter / Shift+Enter 循环）；全部替换前显示影响处数量并二次确认。
AC：正则含捕获组替换（如 `(\d+)章` → `第$1章`）可用。

**FR-FND-02 跨文档查找替换**（P2）
进入跨文档搜索（见 FR-SEARCH-01）结果后批量替换，替换前逐条确认。

### 4.4 自动保存、版本与恢复（FR-SAV）

**FR-SAV-01 自动保存**（P0）
停止输入 2 秒后或每 30 秒自动保存（可配置）；标题栏显示保存状态（未保存/保存中/已保存 + 时间）。
**边界时刻强制 flush**：切换文档、关闭窗口、进入导出/同步方向选择等边界动作前，同步完成保存并持久化光标与滚动位置，不等待去抖。
AC：保存过程不阻塞输入；保存失败（磁盘满等）有明确告警；连续输入后立即切换文档并杀进程，切换前内容零丢失。

**FR-SAV-02 崩溃恢复**（P0）
编辑会话期间维护恢复日志（journal）；进程崩溃/断电后重启，提示恢复未保存内容。journal 本身损坏时按可解析前缀部分恢复并明确告警（不因日志损坏拒绝启动）。
AC：杀进程后重开，最近 5 秒内的输入可恢复。

**FR-SAV-03 版本历史（快照）**（P0）
自动快照：每小时且文档有变化时生成；手动快照：随时可打备注。保留策略：24 小时内全留，之后每日 1 份留 30 天，之后每周 1 份留 1 年（可配置）。快照列表可**只读预览并显示与当前版本的字数差**（P0）、逐段 diff 对比（P1）、回滚（回滚前确认，属 FR-UI-06 模态白名单）。回滚本身可撤销（回滚前的内容自动存为一份快照）。
AC：快照不占用同步带宽（存本地 `.writer/snapshots/`，不同步）。

**FR-SAV-04 本地滚动备份**（P0）
库每日完整备份到 `.writer/backups/`，保留最近 7 份 zip。**备份范围**：`docs/`、`meta.db`、`config.json` 必含（保护快照、统计、AI 对话等仅本地数据）；`attachments/` 可配置（默认排除）；`logs/`、`trash/`、`sync_state.db` 不含（无保留价值或可重建）。可在设置中一键备份到任意位置。

**FR-SAV-05 备份恢复向导**（P1，v1.6 新增）
从 `.writer/backups/` 或用户选择的备份文件恢复：选择备份 → 内容预览（复用快照只读预览）→ **恢复整库**（恢复前将当前状态自动再备份一份，防"恢复本身成为事故"）或**勾选单篇恢复**（恢复到原位置，重名时生成副本）。
AC：清空库 `docs/` 后经向导从昨日备份完整恢复，uuid 与文档树顺序不变。

### 4.5 导出（FR-EXP）

**FR-EXP-01 统一导出框架**（P0）
所有格式经统一 `Exporter` 接口（见 5.1）实现；导出对话框：选择格式 → 排版选项（格式相关）→ 目标路径。支持导出当前文档 / 整个文件夹（批量，文件名 = 文档名）。导出格式集：TXT / MD / DOCX / PDF（DOC 已按决策 D4 移除，后续新格式经 Exporter 接口扩展）。导出完成通知附**"打开所在文件夹"**入口；PDF 与合并导出过程中显示进度指示（长文档可能数秒）；导出对话框**记忆上次使用的格式与目标路径**。

**FR-EXP-02 TXT**（P0）
导出纯文本：格式标记按策略剥离（可配置：保留标题文字、剥离其余标记）；换行符可配置 CRLF/LF；编码 UTF-8（带/不带 BOM 可选）；可选"首行缩进转全角空格"（**默认关**，勾选即接受非标准排版约定）。

**FR-EXP-03 MD**（P0）
导出标准 Markdown：可选择是否包含 frontmatter；图片可选内嵌 base64 或复制附件目录；可选"首行缩进转全角空格"（**默认关**——会产生非标准 Markdown，UI 明示后果）。

**FR-EXP-04 DOCX**（P0）
基于文档模型生成：标题样式（映射 Word 内置样式 Heading 1–6）、加粗斜体、下划线、列表、引用、表格、图片、超链接。文档级排版（字体/字号/行距/首行缩进）写入样式。**范围说明**：V1 为"内容保真"级别排版，不做复杂版式（分栏、艺术字等）。
AC：Word 2016+ 与 WPS 打开无报错，标题出现在导航窗格中。

**FR-EXP-05 PDF**（P0，高级排版 P1）
经排版模板（HTML/CSS）+ WebView2 打印管线生成；**渲染在专用离屏 webview（PDF 渲染舱，见 3.2）进行，不占用编辑区、不产生界面闪烁**。
- **P0（基础排版）**：纸张大小（A4/A5/Letter）、页边距、字号行距；正文与图片分页正确，中文不断行出格。

### 4.7 云同步（FR-SYN）

**FR-SYN-01 WebDAV 账户配置**（P0）
设置中配置：服务器地址、账号、密码（应用密码）、远程根目录。提供"测试连接"。凭据经 **Rust Secrets 服务**（DPAPI）加密存储（前端永不接触明文），绝不写入库文件、不上传。
预置常见服务商模板：坚果云（`https://dav.jianguoyun.com/dav/`）、其他自定义。
**防双引擎冲突**：配置远程目录与每次打开库时，检测库是否位于第三方同步盘管理范围（OneDrive、坚果云客户端等已知特征），命中时显著警告（两套同步引擎管理同一批文件会互相冲突），允许用户了解风险后继续。
AC：库位于 OneDrive 同步目录内打开时出现警告。

**FR-SYN-02 同步范围**（P0）
同步内容：`docs/`（全部 md 与**隐藏清单文件**：墓碑 `.writer-sync.json`、统计聚合 `.writer-stats.json`）、`attachments/`。**不同步**：`.writer/`（数据库、快照、备份、日志——均可由 md 重建或仅本地有意义）。元数据（标签、隐私标记等）写入 frontmatter 随文件同步；**文档树顺序由文件名序号承载（见 FR-DOC-02），随同步天然一致**。
AC：`.writer-sync.json`、`.writer-stats.json` 在文档树/搜索等 UI 中不可见；手工创建的同名文档不受影响（清单由应用独占维护）。

**FR-SYN-03 同步时机与方式**（P0）
- 手动同步（按钮/快捷键）+ 自动同步（文档保存后 10 秒去抖、软件启动时、可配置定时）。
- 增量同步：按文件内容 hash 与 mtime 提示判断变化，未变文件不重复上传；压缩传输（服务端支持 gzip 时）。
- **同步批次与事务性**：每次同步构成一个批次——开始时固化待办文件集，逐文件成功即提交该文件的 sync_state（可中断、可续传）；进程中断/断网后重启，从上次未完成批次自动收敛，不产生半提交状态。引擎状态机（Idle → Scanning → Planning → Executing → Settling / Aborted）显式实现，并经 `sync:state` 事件外显。**退出时机**：应用退出时若批次未完成，优雅中断（事务性保证下次启动收敛），退出前以状态提示告知"未完成的同步将在下次启动继续"。
- 同步状态可视化：文档树图标（已同步/待同步/同步失败/冲突）、底部同步状态栏、同步历史记录（含传输量）。
AC：新建 5 篇文档后同步，在坚果云网页端可见相同目录结构与 md 内容。

**FR-SYN-04 冲突处理**（P0）
同步引擎以 **doc uuid 为主键**维护 `(local_hash, synced_hash, remote_etag)` 三元组，检测到两端同时修改时：
- 不自动合并（V1 无合并能力）；
- 保留两个版本：远端版本下载为 `文档名 (远程冲突备份 YYYYMMDD-HHmmss).md`，并**为其分配新 uuid 重写 frontmatter**（原文档 uuid 不变，冲突关联记入同步历史，杜绝库内重复 uuid），本地版本正常上传；
- 以**非模态通知**提示冲突并附"去处理"入口（见 FR-UI-06）：打开**对比视图**——主区临时双栏（左本地版、右冲突副本，只读 + 复制按钮），提供"保留此版 / 保留彼版 / 手动合并后清理"三个动作（即 V1.0 无多标签/分屏时的承载方案）；V1.1 快照 diff 视图复用同一对比组件。
  **三动作精确语义（v1.7 定案，确认文案如实描述）**：保留此版 = 本地正文不变、删除副本、下次同步**上传覆盖远端**；保留彼版 = 副本内容替换本地正文（替换前自动快照）、删除副本、正常上传；手动合并后清理 = 用户编辑本地后自行删除副本（走墓碑删除副本 uuid，不影响原文档）。任一动作完成即显示"将于下次同步生效"状态。
**判定规则（固定）**：以内容 hash 为权威，文件 mtime 仅作提示（防多设备时钟偏差）；服务器未返回 etag 时，回退为"下载远端内容比对 hash"。
AC：两台设备离线各改同一文档后先后上线，产生冲突副本且双方均不丢内容（A4）；冲突副本持有新 uuid，库内无重复 uuid。

**FR-SYN-05 离线队列与限流保护**（P1）
离线期间操作入队，恢复网络后自动补同步；遇 429/507（坚果云流量超限）时退避重试并明确告知用户流量状况。

**FR-SYN-06 同步安全**（P2）
可选"同步前整库加密"（本地明文，云端密文，密码由用户保管，丢失不可恢复）。第一版仅预留 StorageBackend 加密钩子。

**FR-SYN-07 初次同步方向确认**（P0）
库**首次绑定**远端目录时必须弹出方向选择：上传本地覆盖远端 / 下载远端覆盖本地 / 取消；本地与远端均非空时按文件逐个走 FR-SYN-04 冲突处理。任何情况下不得静默覆盖。
AC：本地与远端均有内容的首次连接，用户未做出选择前不发生任何写操作（A13）。

**FR-SYN-08 删除与改名传播**（P0）
- **身份锚点**：每个文档在创建时分配 uuid，写入 frontmatter `id`；同步引擎以 uuid 识别"同一篇文档"，文件路径仅是当前位置。外部引入文件的 id 校验与分配规则同 FR-IMP-01（按新文档处理并提示）。
- **改名/移动**：检测到"已知 uuid 的旧路径消失 + 新路径出现同一 uuid"时，对远端执行 WebDAV `MOVE`（不重传内容，保留远端版本关联）；文件夹的创建/重命名按目录结构对等处理。**双端离线对同一文档改为不同名**（改名冲突）时，回退为 FR-SYN-04 冲突副本路径。
- **文件夹删除**：对内含**每个文档**生成墓碑 + 删除远端目录；对端将整组文件按原相对路径移入回收站，还原时按原结构一并恢复。
- **删除**：删除记录（uuid + 删除时间）追加到墓碑清单 `docs/.writer-sync.json`；对端同步时将对应文件移入**本端回收站**（可恢复，非直接消失）；若对端在删除时间点之后有本地修改，按 FR-SYN-04 冲突副本逻辑保留内容。远端文件被外部直接删除时，本地同样移入回收站并记录日志。
- **应用独占清单文件规则（固定，v1.7.1 升级）**：`docs/.writer-sync.json`（墓碑）与 `docs/.writer-stats.json`（统计聚合）均为应用独占的结构化数据——任一清单因多端并发写发生自身冲突时，**按集合合并**（墓碑：uuid 求并集、同 uuid 取更晚删除时间；统计：按 device_id/date 求并集），**永不走通用冲突副本路径**；清单被外部删除/损坏时视同空清单并给出高风险提示（墓碑情形旧删除可能复活，可从 sync_state 已知文件集合辅助重建）。**墓碑保留策略**：保留 1 年，GC 仅清理"sync_state 显示各已知文件均已同步过该删除"的记录，无法确认时延后（久未开机设备复活极旧删除属已接受风险）。
AC：A11（删除不复活）、A12（改名走 MOVE 且不重复上传）、A14（并发写墓碑合并）通过；双端并发写统计清单后同样按并集合并、不产生冲突副本文件；文件夹删除后对端整组入回收站；全部传播动作可在同步历史中查阅。

**FR-SYN-09 打开文档的远端更新协议**（P0，v1.6 新增）
同步引擎更新了**当前正打开文档**的磁盘内容时（`doc:external_change` 事件，5.4）：
- 编辑器无未保存修改 → **自动重载**内容（保持光标与滚动位置，撤销栈清空并提示一次）；
- 编辑器有未保存修改 → 走 FR-SYN-04 冲突对比视图流程；
- **保存护栏（防"编辑器踩踏"）**：编辑器每次保存前重新读盘比对 last-read hash，不一致即触发冲突流程，**绝不直接覆盖**——否则远端修改会被本地旧内容+新输入静默吞掉且冲突机制全程无感知。
AC：A15 通过。

### 4.9 AI 能力（FR-AI）

### 4.10 写作目标与统计（FR-STAT）

**FR-STAT-01 写作目标**（P1）

**FR-STAT-02 写作统计**（P1）

**统计机制（固定）**：按文档按日记录字数基线（表 `doc_word_daily(date, doc_uuid, words)`，在日切、保存、同步时更新）；日增字数 = 当日各文档基线差分求和；文档删除后其历史基线冻结保留，不影响当日及既往统计。
**跨设备聚合（v1.5 定案）**：每日增量按 `(device_id, date)` 写入同步清单 `docs/.writer-stats.json`（不含文档明细；合并规则 = 按 device_id 求并集，天然幂等，机制同墓碑清单）；热力图与 streak 基于并集聚合——多设备写作日历不断裂、连续天数不误断。

三栏布局：左（文档树/大纲/搜索切换）+ 中（编辑区）+ 右（AI 面板，可收起）；各栏可拖宽、可隐藏；布局记忆。支持系统 DPI 缩放（125%/150% 不糊不裁切）。窗口最小尺寸 960×640；更窄窗口下侧栏自动折叠为图标栏。

**FR-UI-03 编辑区排版设置**（P0）
编辑区字体（默认霞鹜文楷/思源黑体等系统已装字体，候选列表**带样式预览**）、字号、行距、**段间距**、页宽（固定宽度居中 / 全宽）、首行缩进开关；仅影响屏幕显示与导出默认值，不改变存储内容。**导出排版模板固定浅色纸面，与亮暗主题解耦**（暗色写作不产生暗色导出件）。排版参数（字体/字号/行距/段间距/缩进）**单源定义**，编辑区 CSS 与导出模板同源消费，保证"所见"与"所得"一致。**缩进与段间距属排版型属性，仅作用于排版型格式（PDF/DOCX）**；**文档级排版记忆**（缩进开关等覆盖值）以 frontmatter `layout` 键存储（跨设备，见 6.3/6.4），字体字号等应用级默认不随文档。

**FR-UI-04 启动行为**（P0，v1.3 定案）
默认**直达上次会话**：自动恢复上次库、上次文档、光标与滚动位置（多标签启用后含标签集合）。"启动页"（最近文档、今日进度、快捷入口）为**可选模式**，在设置中开启；今日进度依赖 FR-STAT（V1.0 显示当前会话累计字数）。

**FR-UI-05 首次运行零配置上手**（P0，v1.3 升级）
首次启动**零决策直达编辑**：自动在"文档\Writer\我的文库"创建默认库（内含一篇《欢迎使用》示例文档），直接进入编辑器，全程无选择、无向导。更换库位置、打开/新建其他库的入口位于菜单。V1.1 提供可选的 WebDAV / AI Provider 配置引导（设置中亦可随时进入）。
AC：全新安装后首次启动，用户无需任何点击即可开始输入。
《欢迎使用》内容规范：三分钟上手结构——写作、导出、同步、AI 四个入口各一段并附可点击跳转。

**FR-UI-06 通知中心与打扰治理**（P0）
- **模态白名单（固定）**：仅两类场景允许模态弹窗——破坏性确认（批量删除文件夹、清空回收站、导出覆盖同名文件、快照回滚）与首次同步方向选择（FR-SYN-07）；其余一切通知（同步冲突/失败、保存失败、AI 完成/失败、体检报告）一律非模态；
- **输入保护**：最近 3 秒内有键入时，非紧急通知自动延后至输入停顿再呈现；
- **通知中心**：右下角通知历史聚合沉淀（不因关闭而丢失），可点击跳转对应处理页（冲突处理、同步历史、体检报告、Provider 配置）；
- 保存与同步的常规状态仅由状态栏呈现，永不弹窗。
AC：同步检测到冲突且用户正在输入时，无任何弹窗或通知弹出；停顿后通知出现且可在通知中心找回。

**FR-UI-07 空状态与引导**（P0）
所有空/不可用状态必须给出下一步动作：空库 → 新建文档；未配置 AI 而点击润色/续写/讨论 → 一键跳转 Provider 配置；搜索无结果 → 建议调整关键词；无快照 → 说明快照生成时机。内置帮助与快捷键速查（F1）；帮助内容**本地内置**（断网可用，遵循离线优先原则）。

**FR-UI-08 全局速记**（P2）
系统级全局热键唤起速记小窗（不启动、不切换主界面），内容自动存入库内"灵感"文件夹；下次打开主界面可整理。

### 4.12 设置与更新（FR-SET）

**FR-SET-01 设置中心**（P0）：编辑器、保存、同步、AI、隐私、外观、备份分组；全部设置即时生效。**配置作用域（固定）**：应用级配置（主题、AI Provider 与 Key、快捷键、编辑器默认排版、WebDAV 账号）存 `%APPDATA%\Writer\config.json`，跨库共享；库级配置（库↔远端目录绑定、同步开关）存 `.writer/config.json`；文档级偏好（排版记忆、隐私标记、光标位置）存 frontmatter/文档属性——总表见 6.5 数据存放地图。
**FR-SET-02 自动更新**（P1）：Tauri Updater 检查更新、手动触发下载安装、可关闭；**检查时机默认仅在启动时，通知一律非模态、写作中永不提示**（心流原则）；更新通知附带版本变更摘要（changelog）；更新不触碰用户库数据；升级失败的自动回滚由 updater 机制保证并纳入验证用例。
**FR-SET-03 日志与诊断**（P0）：本地日志（`.writer/logs/`，滚动保留 7 天，**前端与 Rust 落同一日志文件并按 request-id 关联**）；"打开日志目录 / 导出诊断包（脱敏）"入口。**统一错误模型**：跨 IPC 错误码枚举稳定（网络/鉴权/文件/数据库/取消等大类 + 细项），前端据此呈现 FR-AI-08、同步历史等的具体失败原因。
**FR-SET-04 单实例与库锁定**（P0）：应用单实例运行，二次启动聚焦已有窗口；库目录创建锁文件（`.writer/.lock`，含 PID 与进程启动时间戳），检测到库已被其他实例占用时明确提示并阻止打开；持锁进程已死（崩溃残留）时自动接管锁并提示，检测存疑时以"尝试独占打开"兜底判定。
**FR-SET-05 快捷键自定义**（P2）：附录 A 基线快捷键可重绑定；支持导出/导入键位配置。

## 5. 契约与扩展接口设计（为后续开发预留）

契约分两层声明：**Rust trait**（核心能力契约，Rust 内部实现）与**前端 TS 接口**（服务层扩展点）；跨语言边界由 **Tauri command 契约（5.3）与领域事件契约（5.4）**承担，二者为版本化的稳定 API（NFR-11）。后续新增格式/后端/模型只需新增实现，禁止修改调用方。
接口化的第二目标是**可测试性**：StorageBackend 可用 fake + 内存文件系统替身，同步引擎全部用例（A3/A4/A11–A14、双端改名、墓碑合并）可脱离真实网络与磁盘做自动化回归。

### 5.1 Rust trait（核心服务契约）

```rust
trait StorageBackend {       // "webdav" | 未来 "s3" | "onedrive"
    fn test_connection(cfg) -> TestResult;
    fn list(path) -> Vec<RemoteEntry>;      // RemoteEntry.etag 可为空
    fn get(path) -> Vec<u8>;
    fn put(path, data) -> PutResult;        // PutResult 含 etag
    fn mv(from, to);                        // WebDAV MOVE，改名传播专用
    fn delete(path);
    fn transform(dir, data) -> Vec<u8>;     // 预留 FR-SYN-06 同步加密钩子
    // 身份识别（uuid）、删除/改名判定、冲突决策由 SyncEngine 统一完成，后端只做无状态传输。
}

trait LibraryService {       // 库文件单写者（3.3 原则 6）——一切变更的唯一入口
    fn write_doc / rename_doc / move_doc / delete_doc / renumber_folder;
    fn quiesce() -> Guard;   // 快照/备份取一致视图的静默点
}

trait Secrets {              // DPAPI 凭据（WebDAV 密码、AI Key）
    fn set(key, value); fn get(key); fn delete(key);   // 前端永不接触明文
}

trait NetGateway {           // 唯一网络出口（3.3 原则 7，NFR-12 执行点）
    fn chat_stream(provider_cfg, req, abort) -> EventStream;  // AI SSE，取消信号可传播
    fn dav(op) / fn update_check();    // 域名白名单校验在此层强制
}
```

### 5.2 前端 TS 接口（服务层扩展点）

```ts
interface Exporter {
  id: string;                 // "txt" | "md" | "docx" | "pdf" | 未来 "epub"...
  displayName: string;        // 导出对话框显示名
  extension: string;
  supportedOptions: ExportOptionSpec[];  // 声明该格式的可选参数（用于自动生成导出 UI）
  export(doc: DocModel, options: ExportOptions, target: string): Promise<ExportResult>;
  exportMerged?(docs: DocModel[], options: ExportOptions, target: string): Promise<ExportResult>;
  // DocModel 由 DocumentCodec（3.2 M11）从 md 无头解析供给，与 TipTap 编辑器实例解耦；
  // exportMerged 为合并导出（FR-EXP-08）的可选能力，不支持者不出现在合并导出格式列表中。
}

interface AIProvider {        // 门面：消费 NetGateway 流式事件，自身不直接发起网络请求
  id: string;
  chat(req: ChatRequest): AsyncIterable<ChatChunk>;   // 强制流式管线，非流式为其特例
  listModels(): Promise<string[]>;
}

interface SearchProvider {    // 联网搜索（V1.2 启用），同样经 NetGateway 出口
  search(query: string, topK: number): Promise<SearchHit[]>;
}
```

### 5.3 Tauri command 契约（稳定 API，版本化）

前端与 Rust 的全部交互走按域分组的类型化命令（示例域：`library.* / doc.* / folder.* / sync.* / search.* / ai.* / export.* / secrets.* / settings.* / stats.*`）。约定：

- **类型单一来源**：command / 事件载荷 / 错误码由 Rust 侧定义（错误用 thiserror 单源），经 **tauri-specta（或 ts-rs）自动生成 TS 绑定**，禁止两侧手写重复声明（防跨语言类型漂移）；
- 契约版本与应用版本联动：契约破坏性变更必须伴随应用主版本号递增（NFR-11）；
- 参数与返回值显式类型；统一错误码枚举（FR-SET-03），不透传原始异常字符串；
- **前端不持有泛型 fs / sql / shell 能力**（NFR-16），库与数据库操作一律经上述命令；
- 破坏性变更需递增契约版本并保留兼容期（NFR-11）。

### 5.4 领域事件契约（Rust → 前端推送）

| 事件 | 载荷要点 | 消费方 |
|---|---|---|
| `doc:saved` / `doc:renumbered` | doc_uuid、时间 | 状态栏、文档树 |
| `doc:external_change` | doc_uuid、新版本 hash | 编辑器重载 / 冲突分流（FR-SYN-09） |
| `sync:progress` / `sync:state` | 阶段、传输量、文件级状态 | 状态栏、文档树图标 |
| `sync:conflict` | doc_uuid、副本路径 | 通知中心（FR-UI-06） |
| `ai:chunk` / `ai:done` / `ai:error` | 会话 id、增量文本 / 错误码 | AI 面板、润色/续写 |
| `notify:push` | 通知类型与载荷 | 通知中心 |

事件负载显式类型；前端不轮询 Rust 状态。

### 5.5 插件系统（V2，~~仅预留原则~~ **已随 V2.0 取消，2026-10-24**）

V2 的第三方插件将复用上述契约的注册机制（manifest + 沙箱执行），因此第一版实现时须保证 Rust trait 与 TS 接口的注册表均可通过配置声明式扩展，不将任何 Provider 硬编码进业务逻辑。

```
<用户选择的库目录>/

│  ├─ .writer-sync.json       # 墓碑清单（同步，UI 隐藏）
```

md 文件 frontmatter 约定：`id`（uuid，应用创建文档时写入；外部文件缺失时按 FR-SYN-08 分配回写）、`fmt`（**文档格式版本**，启动迁移器依据，见 NFR-10）、`title`、`tags`、`created`、`privacy`、`layout`（文档级排版覆盖：缩进开关等，见 FR-UI-03），除 `id`、`fmt` 外均为可选字段，缺失时按文件信息推断。

### 6.4 DocModel 规范（v1.5 新增）

DocModel = **TipTap JSON 的版本化子集**：TS 侧导出器/Diff/字数/AI 上下文零额外映射成本，Rust 侧只透传不解析；frontmatter `fmt` 即模型版本。约束：

- 块类型与 Markdown 方言（FR-EDT-01）一一映射：heading / paragraph / blockquote / bulletList / orderedList / taskList / codeBlock / table / horizontalRule / image（完整映射表以 schema 文件形式在实现仓库维护，作为往返测试用例来源）；
- 行内标记：bold / italic / underline / strike / code / link / highlight（P1）；
- **未知块/标记降级规则**：无法识别的节点降级为其文本内容（绝不丢弃正文）并记录警告日志；`fmt` 高于当前应用支持版本时提示升级、不盲目解析；
- 往返一致性（FR-EDT-01 AC）以本规范为基准：md → DocModel → md 必须无损。

### 6.5 数据存放地图（v1.5 新增）

| 层 | 位置 | 内容 | 生命周期 |
|---|---|---|---|
| **用户库数据** | `<库目录>`：`docs/`、`attachments/`、`.writer/`（库配置、快照、回收站、墓碑清单、统计聚合） | 全部文稿与库状态 | **永远属于用户**：卸载、升级、重装一律不触碰（FR-PKG-03）；可整体拷贝迁出 |

| **可重建缓存** | `.writer/meta.db`、FTS 索引、缩略图 | 性能优化数据 | 随时可删，由 md 全量重建（FR-DOC-07 体检入口） |

## 11. 成品包装与分发（v1.5 新增）

### 11.1 安装与卸载（FR-PKG）

**FR-PKG-01 安装器**（P0）
- 形态：**NSIS 安装器**（Tauri 默认产物）+ **per-user 安装**（默认安装至 `%LOCALAPPDATA%\Programs\Writer`，不写 Program Files、**免 UAC 提权**——按无签名证书的最坏情况设计，OQ3 签名后不改变安装范围）；
- 快捷方式：桌面 / 开始菜单，安装向导可选勾选；支持静默安装参数（`/S`）；
- SmartScreen 引导：帮助文档提供"更多信息 → 仍要运行"图文指引（无签名期的预期内摩擦）。
AC：标准用户（非管理员）双击安装全程无 UAC 弹窗；快捷方式按勾选生成。
发布件提供 SHA256 校验值（下载页展示）；帮助文档含"被杀毒软件 / SmartScreen 拦截怎么办"图文指引（无签名期的预期内摩擦）。

**FR-PKG-02 WebView2 运行时引导**（P0）
安装器启动时检测 WebView2：缺失 → 内嵌 Evergreen bootstrapper 联网安装；网络失败 → 展示手动下载链接页并中止安装（不产生半安装状态）；安装包体积预算维持 NFR-06（≤30MB，不含引导）。"完全离线捆绑版"（内嵌 WebView2 离线安装包，体积约 +100MB）作为可选下载项在发布时评估。
AC：无 WebView2 的精简 Win10 环境联网安装一次成功；断网环境给出明确的手动下载指引。

**FR-PKG-03 卸载策略**（P0，数据安全红线）
- 卸载器**只删除应用数据**（`%APPDATA%\Writer`：应用配置、日志、崩溃转储），**绝不触碰任何库目录**（6.5 数据地图）；
- 卸载确认页明示"您的全部文稿保留在：〈默认库路径〉"并提供"打开该文件夹"按钮；库内回收站、快照随库完整保留；
- 卸载后库可被再次安装的软件直接打开，零迁移步骤。
AC：写入两篇文档 → 卸载 → 重装 → 打开库，文档与快照历史完整。
重装后启动自动探测默认库路径（`文档\Writer\我的文库`），存在即直接打开——最近库列表虽随卸载清除，默认库无需用户手动找回。

**FR-PKG-04 便携版**（P2，V1.0 不发布；v1.5 定案：仅预留）
数据目录设计预留 `portable` 模式：检测 exe 同目录标记文件（如 `writer.portable`）时，应用数据改存 exe 同目录；便携模式下自动更新禁用（提示改用安装版）。V1 只保证架构不排斥，是否发布视需求评估。

**FR-PKG-05 存储空间面板**（P1）
设置内"存储空间"页：分类展示快照 / 滚动备份 / 回收站 / 附件占用，逐类一键清理；快照与备份保留策略可在此调整（覆盖 FR-SAV-03/04 默认值）。

**FR-PKG-06 文件关联**（不做，明示）
V1 不注册 `.md` 文件关联（不争夺用户既有编辑器关联），仅提供"文件 → 打开"入口导入外部文件。

**FR-PKG-07 开源许可合规**（P0，v1.7 新增）
- 安装向导含许可协议页（自身使用条款 + 开源组件声明）；
- 安装目录带 `LICENSES/` 文件夹：**全部直接依赖**（TipTap、Paged.js、docx、Vue、Tauri、各 Rust crates 等）的许可文本与版权声明，由**构建脚本自动收集生成**（防手工遗漏，依赖变更后自动更新）；
- "关于"页展示开源组件清单（名称 + 许可证 + 版本）；
- 若按 OQ5 捆绑中文字体，OFL 许可文件随包分发。
AC：发布包内可检索到每一个直接依赖的许可文本；新增依赖后重新构建，LICENSES/ 自动包含之。
